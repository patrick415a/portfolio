# Sungho | 내 생각을 움직이는 작업실

**소개와 작업물을 파일처럼 열어 보는 데스크톱 스타일 포트폴리오**

## 프로젝트 목표

소개와 작업물을 담을 공간을 컴퓨터 바탕화면처럼 만들어 보고 싶었습니다. 파일을 열고 창을 옮기는 익숙한 방식에 파스텔 색상과 작은 상호작용을 더해, 방문자가 직접 둘러볼 수 있는 포트폴리오를 만들었습니다.

## 제작 과정

1. **콘셉트 정하기** — 소개, 프로젝트, 메모장, 연락처를 각각의 파일로 나누고 바탕화면에서 열어 보는 구조를 정했습니다.
2. **화면 구성하기** — 파스텔 색상과 아이콘, 파일 창을 중심으로 시안을 구체화하고 화면을 구성했습니다.
3. **프로필 캐릭터 만들기** — 프로필 사진을 캐릭터로 바꾸고, 화면 분위기에 어울리도록 선과 색을 단순하게 다듬었습니다.
4. **기능 구현하기** — Next.js와 React로 창 이동·크기 조절, 테마 전환, 프로젝트 상세와 메모장을 구현했습니다.
5. **사용하면서 다듬기** — 메일 전송을 연결하고, PC와 모바일에서 확인하며 글과 여백, 창 높이, 버튼 배치를 조정했습니다.
6. **프로젝트 데이터 연결하기** — MariaDB에 프로젝트·이미지·기술 정보를 나누어 저장하고, Next.js 서버에서 조회해 Works와 상세 화면에 연결했습니다.

콘셉트와 소개 내용, 원하는 화면의 방향은 직접 정했습니다. 코드 구현과 오류 수정에는 Codex의 도움을 받았고, 프로필 캐릭터는 AI 이미지 생성으로 제작했습니다. 실행 결과를 보며 수정할 부분을 정하고, 세부 조정을 반복했습니다.

### 사용 기술과 도구

| 도구 | 사용 목적 |
| --- | --- |
| Next.js + React | 페이지 구성과 창·아이콘·폼의 상태 관리 |
| TypeScript | 프로젝트 데이터와 컴포넌트의 타입 정의 |

## 포트폴리오 소개

`about_me.txt`에는 소개를, `works`에는 작업물을 담았습니다. `notes.txt`는 방문자가 자유롭게 쓸 수 있는 메모장이고, `contact.txt`에서는 메일을 보낼 수 있습니다. PC에서는 여러 창을 함께 열어 두고, 모바일에서는 한 번에 하나의 창을 볼 수 있습니다.

### 주요 기능

- **About Me:** 캐릭터 프로필, 기본 정보, 소개 문구와 사용 기술 표시
- **My Projects:** MariaDB에서 불러오는 프로젝트 목록, 스크린샷 전환, 소개·사용 기술·GitHub·웹사이트 링크
- **창 조작:** 이동, 크기 조절, 최소화·최대화·닫기와 하단 독에서 복원
- **메모장:** 자유롭게 입력하고 방문자의 브라우저에만 자동 저장하는 `notes.txt`
- **메일 보내기:** 이름·답변받을 이메일·내용 입력과 실제 메일 전송
- **세 가지 테마:** Peach, Sky, Lilac 색상 전환과 브라우저에 저장한 선택값 자동 적용
- **배경 상호작용:** 마우스나 터치를 따라가는 캐릭터의 시선과 천천히 회전하는 별
- **반응형 화면:** PC의 다중 창과 모바일의 단일 창 구성

프로젝트 목록은 MariaDB에서 표시하도록 설정된 항목만 왼쪽부터 배치합니다. 빈 프로젝트 자리는 만들지 않으며, 상세 화면에서는 등록한 스크린샷을 선택해 볼 수 있습니다.

### 조작 방법

| 동작 | PC | 모바일 |
| --- | --- | --- |
| 파일 열기 | 바탕화면 아이콘 두 번 클릭 | 아이콘 한 번 터치 |
| 창 열기·복원 | 하단 독 아이콘 클릭 | 하단 독 아이콘 터치 |
| 창 이동 | 제목줄 드래그 | 화면에 맞춘 고정 배치 |
| 창 크기 조절 | 오른쪽·아래쪽 가장자리 또는 모서리 드래그 | 화면 크기에 맞춰 자동 배치 |
| 최소화·최대화·닫기 | 제목줄 오른쪽 버튼 클릭 | 제목줄 오른쪽 버튼 터치 |
| 프로젝트 상세 | 공개 프로젝트 카드 클릭 | 공개 프로젝트 카드 터치 |
| 테마 변경 | 오른쪽 위 색상 버튼 클릭 | 오른쪽 위 색상 버튼 터치 |

PC에서는 오른쪽 위 초기화 버튼으로 바탕화면 아이콘의 위치를 기본 상태로 되돌릴 수 있습니다.

## 로컬 실행

Node.js 20.9 이상과 MariaDB 서버가 필요합니다. 프로젝트 목록까지 표시하려면 아래 DB 연결 설정과 테이블 준비를 마친 뒤 실행합니다.

```bash
npm ci
npm run dev
```

개발 서버가 출력한 주소를 브라우저에서 열면 됩니다. 기본 주소는 `http://localhost:3000`입니다.

| 명령어 | 용도 |
| --- | --- |
| `npm run build` | 배포용 빌드 |
| `npm run start` | 빌드한 앱 실행 |
| `npm run lint` | 코드 검사 |

### MariaDB 연결 설정

프로젝트 루트의 `.env.local`에 다음 항목을 입력합니다. 실제 계정과 비밀번호는 저장소에 올리지 않습니다.

```env
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=portfolio
DB_USER=사용할_DB_계정
DB_PASSWORD="사용할_DB_비밀번호"
```

`portfolio` DB에는 `projects`, `project_images`, `project_technologies` 테이블이 필요합니다. 서버가 세 테이블을 조회해 화면에 필요한 정보만 전달합니다. DB 설정에 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다. 운영 시에는 해당 DB의 조회 권한만 가진 계정을 권장합니다.

#### 데이터 구성과 화면 연결

| 테이블 | 저장하는 정보 | 화면에서 사용하는 곳 |
| --- | --- | --- |
| `projects` | 제목, 파일 표시명, 소개·상세 설명, 분류·연도, 링크, 상태·표시 여부·순서 | Works 카드와 상세 내용 |
| `project_images` | 프로젝트 ID, 이미지 파일명, 대체 텍스트, 대표 이미지 여부·순서 | 카드 썸네일과 상세 스크린샷 |
| `project_technologies` | 프로젝트 ID, 기술 이름·순서 | 상세 화면의 기술 태그 |

이미지와 기술은 `project_id`로 `projects.id`에 연결합니다. 이미지 파일 자체는 DB에 넣지 않고, `public/assets/projects/` 폴더에 저장합니다. 예를 들어 `guddaji_1.png` 파일을 넣었다면 DB의 `file_name`에도 확장자를 포함한 `guddaji_1.png`만 입력합니다.

페이지를 열면 Next.js 서버가 MariaDB를 조회하고, 조회 결과를 Works와 상세 화면에 전달합니다. 브라우저가 DB에 직접 연결하지 않으며, DB 계정과 비밀번호도 브라우저로 보내지 않습니다.

- `projects.is_visible = 1`: Works에 표시. `status = 'public'`인 프로젝트는 상세 열기 가능.
- `status = 'preparing'`: 제작 중 카드로 표시하며 상세 열기는 비활성화.
- `sort_order`: 작은 값부터 표시하며, 같으면 ID 순서로 정렬.
- `project_images.file_name`: `public/assets/projects/`에 넣은 이미지의 확장자를 포함한 파일명.
- `is_thumbnail = 1`: 대표 이미지. 지정하지 않았다면 첫 이미지 사용.
- `slug = 'portfolio'`: 현재 보고 있는 페이지로 표시하고 사이트 링크 비활성화.
- 상세 설명의 빈 줄은 문단을 구분합니다.

DB 변경은 페이지를 다시 접속하거나 새로고침하면 반영됩니다. 텍스트·기술·순서 수정에는 재빌드가 필요하지 않습니다. 운영 중 새 이미지 파일을 추가할 때는 서버를 재시작하고, 코드 수정 시에는 다시 빌드합니다. `.env.local` 수정 후에도 서버를 재시작합니다.

DB가 비었거나 연결에 실패해도 바탕화면과 다른 앱은 사용할 수 있으며, Works에서 빈 목록 또는 재시도 안내를 표시합니다.

관련 코드:

- [`src/lib/db.ts`](src/lib/db.ts): 서버 전용 DB 연결 풀 관리
- [`src/lib/projects.ts`](src/lib/projects.ts): 세 테이블 조회 및 화면 데이터 변환

### 이메일 전송 설정

메일 전송을 사용하려면 [Web3Forms](https://web3forms.com/)에서 Access Key를 발급받고, 프로젝트 루트에 `.env.local` 파일을 만든 뒤 아래 내용을 입력하세요.

```env
NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY=발급받은_Access_Key
```

기존 구따지의 `VITE_WEB3FORMS_ACCESS_KEY` 이름도 지원합니다. 두 이름을 함께 설정하면 `NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY`가 우선 적용됩니다.

설정 후 개발 서버를 다시 시작하세요. 키가 없으면 메일 전송 버튼이 비활성화되며, 나머지 기능은 사용할 수 있습니다. 메일은 Access Key에 연결된 주소로 전송되고, 폼에 입력한 이메일은 회신 주소로 사용됩니다.

Web3Forms Access Key는 브라우저 공개용입니다. `NEXT_PUBLIC_` 환경 변수는 빌드된 브라우저 코드에 포함되므로 비밀 정보 저장 용도로 사용하면 안 됩니다. 배포 시에도 빌드 환경에 키를 설정해야 합니다. 자세한 전송 동작은 [`docs/contact-form.md`](docs/contact-form.md)를 참고하세요.

`.env.local`, 설치 패키지, 빌드 결과, 원본 사진과 보관용 디자인 자료는 저장소에 포함하지 않습니다.
